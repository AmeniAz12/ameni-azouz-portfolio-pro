DevSecOps Pipeline for a FastAPI SOC/OSINT Application

Secure CI/CD pipeline for a FastAPI SOC OSINT application. The project automates checkout, SAST, secret scanning, Docker build, image scanning, DAST staging, ZAP Baseline, report archiving, local Kubernetes and monitoring.

Project objective

Build a complete DevSecOps pipeline for a FastAPI SOC OSINT application by automating security controls, dynamic testing, evidence archiving and deployment preparation.

Laboratory environment

The project uses Jenkins in Docker, an application Docker image, local DAST staging, a Kind Kubernetes cluster and a Prometheus/Grafana monitoring stack.

  • FastAPI / Python SOC OSINT application
  • Jenkins running in Docker
  • Docker build with devsecops-image
  • Local DAST staging through Docker network ci-net
  • Local Kubernetes with Kind
  • Monitoring with Prometheus, Grafana, Alertmanager, Pushgateway and Node Exporter

Methodology

01

Pipeline as code

The Jenkinsfile fixes the stage order: checkout, Bandit, Gitleaks, Docker build, Trivy, DAST staging, ZAP Baseline, final result and post actions.

02

Code and secret controls

Bandit scans app.py, webapp.py and osint_reporter, while Gitleaks searches for real secrets in the repository.

03

Image and DAST

Docker produces an application image scanned by Trivy. The container is then launched in local staging for an OWASP ZAP Baseline scan.

04

Ops and observability

The same Docker artifact is used for Kind Kubernetes, then Prometheus, Grafana and Alertmanager provide runtime visibility.

Risk and impact

The project demonstrates an operational DevSecOps chain, but the Trivy scan shows that the Docker image still needs hardening before strict production use. The current policy remains warn-only for the academic demonstration.

  • HIGH/CRITICAL vulnerabilities in the image if left unresolved.
  • Trivy warn-only policy is acceptable for demo but insufficient for production.
  • ZAP Medium/Low alerts should be tracked in a security backlog.
  • Monitoring should be extended to cover more application metrics.

Recommendations

  • Harden the Trivy policy to block selected critical findings in production.
  • Fix or justify image vulnerabilities reported by Trivy.
  • Add automated functional tests in addition to security gates.
  • Extend application monitoring and business alerts.
  • Industrialize image push to a registry and continuous Kubernetes deployment.
  • Keep systematic report archiving as audit evidence.
